4、web项目中安全问题怎么处理？

怎么做？

5、单点登录
sso  登录一次访问所有相互信任的系统
cas 中央认证服务
oauth2  授权的协议，只需要授权方与被授权方遵守这个协议去写代码提供服务，那双方就是实现了oauth模式

总结：cas与oauth2
CAS：授权服务器，被授权客户端
OAuth2:主系统，授权系统（给主系统授权用的，也可以跟主系统是同一个系统），第三方系统
CAS登录和OAuth2在流程上的最大区别就是，通过ST或者code去认证的时候，需不需要预先商量好的密码。

6、前端性能优化
常见指标：
fcp 首屏加载时间
fp  首次绘制时间
lcp 最大内容绘制时间
tti 用户可交互时间
tbt 页面阻塞时间
seo 搜索引擎优化

6.1 编码优化
数据读取
    尽量在局部作用域使用缓存
    避免嵌套过深，数据扁平化
循环
    尽量减少循环次数
    避免循环中进行大量计算，重复计算，使用缓存
    避免使用for in,因为会枚举原型对象，耗时大于普通循环
条件流程性能
    map/object > switch > if else
cookie
    去除不必要cookie
    压缩cookie大小
    设置domain与过期时间
dom优化
    减少访问dom次数
    减少重流重绘
    使用时间委托，避免大量事件绑定
css
    层级扁平
    特定选择器，优于层层查找
    减少通配符和属性选择器
    减少不必要的多余属性
    优先css动画
    使用link替代@import
html
    减少dom数量
    避免img空标签，src为空仍然会发起请求
    图片提前指定宽高或者脱离文档流，减少页面回流
    语义化标签，有利与seo与浏览器解析
    减少table布局

6.2 页面基础优化
引入位置
    css head引入，js body底部引入
减少请求
减少文件体积
    删除多余代码  tree-shaking uglifyjs code-splitting
    混淆/压缩代码  gzip压缩
    多份编译文件按条件引入
        现代浏览器支持es6的直接给es6，低端浏览器给编译后的es5文件
        利用script type='module'条件引入
图片优化
    业务场景 合适质量，合适尺寸
    平台   合适格式
    雪碧图
    iconfont / svg
使用缓存
    浏览器缓存
    cdn缓存
        html放于自己的服务器，js、css、图片上传cdn服务器，文件带上hash值
        资源放于对个不同域名的cdn  浏览器对单个域名请求有限制
    服务器缓存
        redis等
    数据缓存

6.3 首屏渲染优化
    css、js分割，首屏依赖文件最小
    非关键性的文件异步加载或者懒加载，避免阻塞首页渲染
    使用dns-fetch、preconnect、prefetch、preload等，加快文件传输
    控制好web字体
    合理使用localstorage、service-worker
    重要元素优先渲染、视窗内的元素优先渲染
    服务端渲染 ssr
    优化用户感知 动画、骨架屏等

7、计算首屏事件，白屏事件
PerformanceObserver 监听加载性能指标

const time = Date.now() - performance.timing.navagationStart;
但是不是很准确

另一种思路？
-- dom的增加、修改、删除会触发MutationObserver
-- 每次dom变化都会计算出一个相对时间和dom分数变化，并存入一个observerData数组中
-- 而后处理observerData数组，计算dom变化时分数的差值，取dom分数变化最大的时间点作为首屏事件的取值点
-- 因为首屏并不是所有dom的渲染，所以不能最后一项dom加载完的时间
